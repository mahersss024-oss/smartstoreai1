# إصلاح اختبار الملف العام وتحذيرات الفحص والبناء

التاريخ: 20 أكتوبر 2026. النطاق المصرح به في هذه الجولة: معالجة تعارض اختبار
`profile` وتحذير lint وتحذيرات تتبع `.data`. التغييرات مستقلة عن مراجعة
المشروع الشاملة السابقة؛ لا تعني معالجة جميع نتائج تلك المراجعة.

## السبب والإصلاح

### عقد قراءة ملف المعلن

أعاد اختبار baseline الفشل: `GET /api/marketplace/users/[userId]/profile`
يرجع `404` لبائع مفقود بينما جدول الاختبار يتوقع `401`. التحقيق أثبت أن
القراءة عامة: صفحة المعلن وصفحة الإعلان تستخدمان `getPublicSellerProfile`
بلا جلسة، وتُعرض بيانات عامة وإعلانات منشورة. المسار الجديد ورث افتراضيًا
تصنيف session من بادئة `/api/marketplace/` في جدول الاختبارات.

أضيف استثناء **GET المحدد وحده** في
[route-contracts.ts](../scripts/testing/route-contracts.ts). بقيت assertions
`401` للجلسة المفقودة والمزورة والمنتهية على المسارات المحمية كما هي؛ لم
يُضف شرط تسجيل دخول إلى صفحة عامة للحصول على اختبار أخضر.

في [مسار profile](../app/api/marketplace/users/[userId]/profile/route.ts)،
استُبدل binding الهاتف غير المستخدم بنسخة من الكائن ثم حذف `phoneNumber`.
الاستجابة تظل تستبعد الهاتف دون تعديل الكائن الأصلي أو إضعاف قاعدة lint.

أضيفت [اختبارات سلوكية](../tests/public-seller-profile-route.test.ts) تغطي:

- قراءة الضيف وإرجاع الإعلانات المنشورة فقط، مع بقاء المسودة والموقوفة
  خارج الاستجابة.
- `404` للبائع المفقود أو الذي لا يملك إعلانًا منشورًا في المخزن الملفي.
- عدم تسلسل رقم هاتف موجود فعلًا في نتيجة قراءة Prisma المستبدلة.
- `404` للحساب المفقود أو المحذوف، وقراءة الحساب الصحيح ذي صفر إعلانات.

فرع Prisma يستبدل القراءات الخمس كلها؛ هذه اختبارات handler والخصوصية،
وليست إثباتًا لاتصال PostgreSQL أو سياسات RLS أو معاملات قاعدة حقيقية.

### تتبع مجلد البيانات أثناء البناء

كانت دوال المسار في مخازن السوق وWeb Push وMobile Push ترجع
`join(process.cwd(), '.data')` أولًا، ثم يُضاف اسم الملف لاحقًا. يتتبع
Turbopack هذا التعبير الوسيط بوصفه دليلًا، فتتسع مراجع البناء إلى محتوياته.
السلوك مدعوم بآلية
[تتبع المسار في المصدر الرسمي](https://github.com/vercel/next.js/blob/canary/turbopack/crates/turbopack-ecmascript/src/references/raw.rs).

أصبحت كل دالة ترجع مسار الملف الكامل مباشرة في `join` واحدة، مع المحافظة
على أسماء الملفات و`SMARTSTORE_DATA_DIR` وtrim والمسار الافتراضي. لم تُضف
استثناءات تتبع أو أعلام تجاهل للتحذير. التغييرات في
[store.ts](../agent/marketplace/store.ts)،
[push-subscriptions.ts](../agent/marketplace/push-subscriptions.ts)
و[mobile-push-tokens.ts](../agent/marketplace/mobile-push-tokens.ts).

فُحصت قوائم NFT المحلية قبل البناء وبعده، دون فتح الملفات المشار إليها:

| مرجع فريد داخل `.data` | قبل | بعد |
| --- | ---: | ---: |
| جميع الملفات | 15,989 | 2 |
| ملفات PostgreSQL المحلي | 1,941 | 0 |
| أدوات الفحص والكاش | 14,022 | 0 |
| `local.json` | 1 | 0 |

المتبقي ملفا التخزين المعروفان `marketplace-store.json` و
`push-subscriptions-store.json`. هذه مراجع manifest محلية، **وليست دليلًا
على نشر ملفات أو تسريبها**. لم تُقرأ محتويات أسرار أو بيانات عميل أثناء
فحص القوائم. الأدلة: [قبل](../.data/project-repair/tracing-before.json)
و[بعد](../.data/project-repair/tracing-after.json).

تثبت [اختبارات الاستمرار الجديدة](../tests/local-store-persistence.test.ts)
حفظ المخازن الثلاثة ثم قراءتها من عملية أخرى، للمسار الافتراضي وoverride
مطلق ونسبي مع مسافات. تعمل بياناتها الصغيرة داخل مجلدات معزولة في `.data`
فقط، ولا تتصل بالشبكة أو قاعدة البيانات؛
[fixture](../tests/fixtures/local-store-persistence.ts) يرفض السياق غير المعزول.

### نطاق ESLint

كشف التشغيل الكامل أيضًا ملفات JavaScript لطرف ثالث نزلها Chrome داخل
ملفات متصفح الفحص في `.data`، وكان ESLint يعاملها كشيفرة مشروع. أضيف
`.data/**` إلى قائمة الملفات المولدة المتجاهلة في
[eslint.config.mjs](../eslint.config.mjs)، إلى جانب `.next` والتقارير الموجودة.
لم تتغير قواعد فحص شيفرة التطبيق أو الاختبارات، ولم يُستخدم auto-fix.

## التحقق

النتائج النهائية ومعلومات التشغيل في
[summary.json](../.data/project-repair/summary.json). السجلات الحالية تحت
`.data/project-repair/`؛ السجلات الأقدم تحت `.data/environment-audit/` تصف
baseline قبل الإصلاح ولا تُستبدل بنتائج الجولة الحالية.

| الفحص | النتيجة |
| --- | --- |
| إعادة baseline المركزة قبل التعديل | فشلان محسوبان من تعارض profile نفسه |
| اختبارات مركزة بعد الإصلاح | 127/127 ناجحة |
| استمرار التخزين في عمليات منفصلة | 3/3 ناجحة |
| TypeScript | نجح بعد إضافة الاختبارات الجديدة |
| ESLint | نجح دون أخطاء أو تحذيرات |
| Build | نجح، نحو 61.5 ثانية، دون تحذيرات |
| مجموعة Node الكاملة | **881 اختبارًا: 863 ناجحًا، صفر فشل، 18 متجاوزًا**؛ نحو 203.5 ثانية |
| Playwright المختار | 4/4 ناجحة على سطح المكتب والمحمول، دون flaky أو retries |
| HTTP على نسخة البناء الجديدة | ملف عام 200، مفقود 404، مسار follow المحمي للضيف 401 |
| DB integration | لم يُشغّل؛ لم يُغير schema أو migrations أو بيانات القاعدة |

فحص HTTP أكد استبعاد الهاتف والبريد، وإرجاع أربعة إعلانات fixture منشورة
وبقاء `Cache-Control: no-store`.
[الدليل](../.data/project-repair/http-profile.json).

لم تتغير اعتماديات التطبيق أو ملف القفل أو تصميمه أو إعدادات الإنتاج.
تغييرات auth/session التي كانت موجودة قبل هذه الجولة بقيت كما هي.
أُوقف خادم الفحص على المنفذ 3197 بعد اكتمال التحقق.
