# Test Run: 2026-10-16

## Status

Testing infrastructure and executable coverage were expanded. Complete coverage of
every business function, button and state is **not finished**. No application
functions, routes, UI layout, dependencies or database migrations were changed.
Changes were not committed or pushed.

## Verified Results

| Check | Result |
| --- | --- |
| TypeScript `tsc --noEmit` | Passed |
| Full ESLint run | Passed |
| Node suite with coverage | 655 passed, 0 failed, 4 database tests skipped |
| Real PostgreSQL integration, separate run | All 4 passed against a fresh isolated database; all 22 migrations applied |
| First expanded browser run | 277 passed, 2 skipped, 1 mobile image performance failure out of 280 cases |
| Final targeted browser matrix | All 232 passed on desktop/mobile Chromium, without retries |
| Production build | Passed as part of the browser server preparation |

The final 232-case run included all route contracts, all page/access checks with
asserted final URLs, image-loading checks and the new account control interactions.
It is not a claim that the entire browser suite passed in a single final run.
The initial two skips were the desktop-only exclusion of the mobile keyboard
scenario and the duplicated mobile performance audit, whose parent test already
exercises mobile/tablet viewports.

Initial mobile first-image LCP was 4,408 ms against the unchanged 2,500 ms budget
while coverage and browser suites were running concurrently. In the separate final
run it was 1,416 ms on mobile and 1,400 ms on desktop, with CLS zero. This comparison
suggests host contention, but does not prove the cause or erase the initial failure.
Keep the original trace and investigate if the budget breach recurs. The threshold
was not relaxed, and application code was not changed to obtain the passing rerun.

The isolated PostgreSQL cluster and temporary browser servers were stopped.
No production database was used for these tests.

## Inventory and Measurement

- 254 executable source files in the configured inventory scope.
- 26 page definitions and 82 explicitly exported HTTP operations.
- 3,289 source function definitions, including anonymous callbacks and scripts.
- 435 recognized JSX control definitions, not necessarily 435 distinct buttons.
- Node tests measured 138 source files; 116 were never loaded by that suite.
- Native executed-module coverage: lines 73.04%, branches 80.03%, functions 83.78%.

These percentages exclude never-loaded files and browser execution. Transpiler
helpers may affect native function/branch counts. They are **not total project
coverage** or the percentage of business functions verified. Static assets,
generated metadata/internal framework endpoints and infrastructure are not all
represented by the explicitly exported HTTP-operation count.

## Still Required

Every inventoried business operation and control needs an explicit mapping to a
scenario and its observable outcome before claiming complete functional coverage.
Existing browser tests already exercise some controls; an unmapped inventory item
does not automatically mean it is never clicked. Successful admin/moderator/owner
database workflows, all permission combinations, real OAuth/AI/storage/push/native
integrations, additional dynamic-record states, physical browsers/devices and
production resilience are not certified by this run.
