# ربط عمليات التطبيق باختبارات السيرفر

تبدأ هذه الخريطة من استدعاءات الشبكة في كود تطبيق الجوال، ثم تربطها بطريقة
HTTP ومسار السيرفر والسيناريوهات المسماة التي راجعنا تأكيداتها الفعلية.
مجلد التطبيق الافتراضي هو `AI` داخل المشروع الأساسي، ويمكن تمرير مسار آخر.

```powershell
# تحقق من الربط وأنشئ التقرير، دون تشغيل اختبارات أو اتصال بقاعدة بيانات.
pnpm.cmd test:mobile-contracts

# شغّل ملفات الاختبار المرتبطة بالخريطة وسجّل نتيجة كل سيناريو.
pnpm.cmd test:mobile-contracts --run-node --run-mobile --run-postgres

# يمكن إعادة جزء واحد فقط عند الحاجة.
pnpm.cmd test:mobile-contracts --run-mobile
pnpm.cmd test:mobile-contracts --mobile-root C:\path\to\mobile
```

يُنتج الأمر `coverage/mobile-operation-map.md` للقراءة، وملف JSON بالاسم
نفسه للمعالجة الآلية. يحتوي كل بند على عملية التطبيق، ومواضع استدعاء المسار،
ومعالج السيرفر، والأثر المتوقع، واسم الاختبار وما تثبته تأكيداته، ونتيجته
المسجلة، والفحوص المتبقية. فروع الإجراءات التي تشترك في المسار نفسه، مثل
إرسال الرسالة وحذفها ومشاركة الرقم والحظر، لها بنود منفصلة ومراجع لفروعها.

المراجع المنسقة موجودة في `scripts/testing/mobile-account-contracts.ts`
و`mobile-marketplace-contracts.ts`. لا تُستنتج تغطية السلوك من مجرد استيراد
ملف أو وجود اسم مسار في الاختبار. الجرد الآلي محدود بالأنماط المعلنة في
التقرير؛ يبقي النقل العام والروابط الخارجية ظاهرين بصورة مستقلة.

## معنى نتيجة الاختبار

تأتي النتيجة من أحداث مشغّل Node، وتُربط باسم الاختبار وملفه وبصمة مصدره
وبصمة كود التطبيق أو السيرفر وإعدادات المشروع ومساعدات الاختبار وناقل المحاكاة.
إذا تغيّر المصدر أو هذه الاعتماديات تظهر النتيجة
`stale-result`. ولا يكفي نجاح مجموعة عامة لاعتبار سيناريو غير مسجل ناجحًا.

`reviewed-scenarios-passed` تعني أن التأكيدات المرتبطة بالبند نجحت؛ لا تعني
أن جميع حالات العملية قد غُطيت. قد يثبت اختبار رفض الزائر أو صحة عملية في
المستودع، مع بقاء استجابة HTTP الناجحة أو تجربة الجهاز ضمن الفحوص المتبقية.

اختبارات Playwright لها تقرير مستقل؛ لا يقدّم اختيار ملفها في الإعدادات
دليلًا على نجاحه، ولا تُحوّل نتائجها السابقة تلقائيًا إلى نتيجة حديثة مرتبطة
ببصمة المصدر في هذه الخريطة.

## العزل وحدود الفحص

اختبارات Node تستخدم مخزنًا مؤقتًا وعزلًا للمزوّد. اختبارات عميل الجوال
تنفّذ الأدوات ودوال الحالة بهياكل الاختبار الموجودة؛ فهي لا تشغّل واجهة
Android أو iPhone على جهاز فعلي.

تشغيل PostgreSQL يستخدم العنقود المحلي المخصص فقط على
`127.0.0.1:55432/smartstore_codex_test`، ويعيد حالته السابقة بعد التنفيذ.
يتحقق المشغّل من الوجهة وأسماء ملفات الاختبار، ويتجاوز تحميل `.env.local`،
ولا يطبق ترحيلات على قاعدة الاختبار الموجودة. لا يستبدل هذه القاعدة بقاعدة
مستضافة. ويُنظّف كل اختبار
بياناته التجريبية وفق حمايته الموجودة.

تظل مصادقة المزوّد الحقيقية، وإعدادات التوقيع، ورفع R2 ومعالجة Cloudflare
الحيّة، ووصول الإشعارات، وتجربة الأجهزة والشبكات الفعلية فحوصًا مستقلة.

## تحديث الخريطة

إضافة استدعاء API جديد دون ربطه، أو حذف مسار، أو نقل ملف، أو تغيير اسم
سيناريو أو فرع إجراء مربوط يجعل التحقق يفشل ويعرض المرجع الذي يحتاج مراجعة.
تضاف اختبارات سلوكية عندما تثبت المراجعة نقصًا، مع إبقاء حدود التأكيد واضحة.

أضيفت اختبارات فعلية لمسار تسجيل Google الأصلي وقبول الاتفاقية ونتائج الجلسة
في `tests/google-native-route.test.ts`، ولمعالجَي اختيار الصورة الرئيسية
وحذفها وصلاحياتهما وإعادة الطلب في `tests/listing-image-actions-route.test.ts`.
هذه اختبارات للوظائف القائمة، ولم تتطلب تعديل وظائف المنتج.

## التشغيل الإلزامي في GitHub

تضيف `Production Gate` مهمة `Mobile And PostgreSQL Contracts` لكل دفع إلى
`main` وطلب دمج وتشغيل يدوي. تجلب نسخة مثبتة بالتزام Git كامل من مستودع
التطبيق إلى `AI`، وتثبت مكتبات المشروعين بملفَي القفل، وتشغّل فحص أنواع
التطبيق وتنسيقه واختباراته، ثم خريطة العمليات والاختبارات المرتبطة بها.
يُحدّث التزام التطبيق في ملف workflow عند اعتماد نسخة جديدة منه.

قاعدة PostgreSQL في هذه المهمة خدمة مؤقتة مخصصة للتشغيل، على العنوان
المحلي والاسم المحميين نفسيهما. المشغّل المحمول
`scripts/testing/run-ci-postgres-contracts.mjs` يرفض أي وجهة أخرى، ويتحقق من
صلاحية إنشاء قاعدة اختبار المسح الشامل، ويطبّق الترحيلات الملتزمة على خدمة
الاختبار هذه، ثم يشغّل جميع ملفات اختبارات PostgreSQL المكتشفة تسلسليًا.
يحتاج تفعيل `SMARTSTORE_CI_DB_TESTS=1`، ولا يُستخدم بدل المشغّل المحلي
العادي دون هذا التفعيل الصريح.

تجمع حالة `Production Readiness` نتائج الجودة والمتصفح وAPI والجوال/قاعدة
الاختبار. تفشل إذا فشلت أي مهمة مطلوبة أو أُلغيت أو تخطّاها التشغيل.
لا يغيّر هذا الملف حماية الفروع أو إعداد نشر AWS؛ ربط الدمج أو النشر بهذه
الحالة خطوة إعداد مستقلة. تقارير النتائج تُرفع كمرفقات للتشغيل حتى عند الفشل.
