# نشر إصلاحات موثوقية السيرفر — 12 نوفمبر 2026

هذه التغييرات تخص السيرفر وWorker الصور. لا تتطلب إصدارًا جديدًا لتطبيق Android أو iPhone، ولا تغيّر مسارات API العامة أو صلاحيات العميل الأساسية.

## ترحيلات قاعدة البيانات

تضاف أربعة ترحيلات دون إنشاء جداول تطبيق جديدة:

- `20261112010000`: إضافة `sessionVersion` لإبطال الجلسات عند تعطيل الحساب، و`chatUsage` لضبط الطلبات المتزامنة للشات. بيانات الاستخدام لا تغيّر وقت تعديل الملف الشخصي ولا تنشئ أحداث أدلة.
- `20261112020000`: إضافة دالة تطبيع عنوان ثابتة وفهارس `pg_trgm` والبحث في التصنيفات. تبقى المطابقة حرفية مع الفلاتر الحالية، وتبقى نتيجة التشابه محدودة بأفضل 20 إعلانًا.
- `20261112030000`: إضافة علامة حفظ صور الاستعادة إلى إيصالات تنظيف الصور القائمة.
- `20261112040000`: تحديث دوال التقاط صور الإعلانات وصور الحساب المحذوفة أو المستبدلة، وترقية الإيصالات المؤجلة لضمان حفظ النسخة الخاصة قبل حذف الملف العام عند تفعيل الأرشفة.

تُطبّق الترحيلات على PostgreSQL المحلية المعزولة أولًا، ثم عبر مسار النشر المعتاد بعد نجاح Production Gate. يلزم أن يسمح مستخدم قاعدة الإنتاج بتثبيت `pg_trgm`. لا تستبدل إعدادات الإنتاج بقيم الاختبار.

## أرشيف الصور الخاص

ينشئ النظام نسخ استعادة من ملفات العرض المحوّلة الموجودة فقط؛ لا يحتفظ بالصورة الأصلية التي رفعها العميل ولا يعيد إنشاءها.

1. أنشئ حاوية R2 خاصة مثل `souqhamad-image-recovery`، بلا نطاق عام وبلا رابط تطوير عام.
2. امنح بيانات اعتماد السيرفر صلاحية قراءة حاوية الصور وكتابة حاوية الاستعادة. تحقّق من صلاحية `CopyObject` وقراءة الترويسات `HEAD` بين الحاويتين.
3. اضبط `SMARTSTORE_IMAGE_RECOVERY_BUCKET` باسم الحاوية. غياب المتغير يبقي الأرشفة معطلة ويحافظ على طريقة الحذف السابقة.
4. اضبط سياسة احتفاظ مستقلة للأرشيف تغطي نافذة استعادة قاعدة البيانات. مثال تشغيلي: 30 يومًا للصور، مع مراقبة اللقطات اليدوية الأقدم التي قد تحتاج هذه الصور. إعداد RDS المؤكد سابقًا هو 7 أيام؛ لا يُغيَّر تلقائيًا بهذا الكود.
5. جرّب حذف صورة لحساب اختبار، وتحقّق من وجود نسخة خاصة سليمة قبل حذف النسخة العامة.

المفتاح المحفوظ هو `recovery/v1/<أول 16 حرفًا من SHA256 لاسم الحاوية>/<مفتاح الصورة>`، وتُحفظ بيانات المصدر للتحقق من اكتمال النسخ. فشل النسخ أو التحقق يبقي إيصال التنظيف معلقًا لإعادة المحاولة. لا يُضاف مسار استعادة أو تحكم تدميري إلى لوحة المالك.

لاستعادة حادث حقيقي: تُستعاد RDS إلى قاعدة مستقلة أولًا، ثم تُفحص مراجع الصور ويُعاد المطلوب من الأرشيف إلى مفاتيحه العامة، وبعد التحقق يُخطط تحويل اتصال الخدمة. استعادة RDS وحدها لا تستعيد ملفات R2 المحذوفة.

## معالجة الصور والطوابير

تُحدَّد عمليات معالجة الصور التي تمر بالسيرفر بعدد متزامن وطابور انتظار محدود ومهلة معالجة. تبقى حدود نوع الملف وحجمه وأبعاده والصلاحيات نافذة؛ لا تُعطَّل طريقة الرفع الاحتياطية.

يضيف إعداد Worker مستهلكًا محدود المحاولات إلى `souqhamad-image-uploads-dlq`. تُنشر نسخة السيرفر الداعمة أولًا، ثم Worker وإعداد المستهلك. حالات الفشل النهائية تُعتمد عبر مسار claim الداخلي والسر القائم، مع حماية أي معالجة أو ترقية نشطة وعدم إعادة فتح حالة نهائية.

يجب التحقق في Cloudflare من وجود مستهلك DLQ الصحيح وانخفاض الرسائل المتراكمة، ثم تجربة رفع لحساب اختبار. اختبارات المحاكاة المحلية لا تثبت إعداد الحساب الحي.

يمكن ضبط Lifecycle للحاوية المؤقتة على بادئتي `intake/v1/` و`staged/v1/` بعد مهلة تتجاوز عمر العمل والتوقيعات؛ المثال المقترح 48 ساعة. تُراجع القواعد الحالية قبل إضافة أي قاعدة؛ لا تُطبَّق هذه السياسة على حاوية الصور المنشورة أو الأدلة.

## التحديثات اللحظية والشات

اتصالات SSE محدودة بالذاكرة وعدد الاتصالات، وتُجدّد قبل حد طلب App Runner، مع إعادة التحقق من الحساب والصلاحيات قبل دفعات الإرسال. تظل إعادة جلب البيانات عبر API مصدر الحقيقة.

عند ضبط بيانات Redis REST الحالية، تتبادل النسخ إشارات التحديث عبر Redis Stream محدود الحجم. `SMARTSTORE_REALTIME_BACKEND=memory` يعطل هذا الربط. يلزم اسم stream مستقل لكل بيئة وصلاحيات `EVAL/XADD/EXPIRE/XREAD`. لا تُضاف خدمة مدفوعة أو بيانات اعتماد تلقائيًا.

للشات حد متزامن افتراضي بطلبين لكل حساب وحد للمخرجات في خطوة النموذج. الحد اليومي الافتراضي صفر، أي غير مفعّل، وتفعيله قرار تشغيل مستقل. تبقى وظائف حمد الحالية كما هي.

## التحقق والنشر

تُراجع نتائج اختبارات الوحدة وWorker وPostgreSQL وواجهات API وPlaywright والبناء والتحليل الأمني قبل الدفع. لا يُعد تجاوز اختبار أو غياب مزود حي نجاحًا لذلك المسار.

الدفع إلى فرع الإصلاح يتيح مراجعة التغييرات في طلب دمج. النشر الإنتاجي يمر عبر Production Gate وفرع `production` الحالي. إعداد حاوية الاستعادة وRedis ومستهلك Cloudflare والتحقق من دورة رفع حية خطوات تشغيل منفصلة عن نجاح الاختبارات المحلية.
