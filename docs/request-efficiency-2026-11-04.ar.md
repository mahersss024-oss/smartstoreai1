# تقليل الطلبات واستمرار نشر الإعلان — 4 نوفمبر 2026

## النطاق والعقود

التطبيق المستقل في `AI/`، والسيرفر في جذر هذا المستودع. الهدف تقليل العمل المكرر مع الاستجابة السريعة وحداثة البيانات، وليس تعطيل القراءات اللازمة. لم تتغير مسارات HTTP أو عقودها، ولا مخطط Prisma أو الترحيلات أو الصلاحيات أو حساب الرسوم أو دور حمد. لم تُضف خدمة سحابية أو مكتبة أو طبقة كاش بديلة، ولم تُرقَّ موارد AWS.

الاستثناء المرئي المتفق عليه: تأكيد النشر ينقل العميل إلى «إعلاناتي» ببطاقة مؤقتة، بينما تتابع العملية عملها؛ لا تعني البطاقة أن الإعلان نُشر فعليًا.

## التطبيق

- `src/core/realtime-query-refresh.ts`: تحديث فوري، وطلب جارٍ مشترك لكل query، ثم استدراك عند وصول حدث أثناء القراءة. يعاد التحقق عند الاتصال بمصدر أحداث جديد، دون إلغاء القراءة وإعادتها لكل حدث. تبقى الصفحات والترتيب والاستدراك الدوري الحالي.
- `src/core/visible-query.ts` و`visible-query-read.ts`: ربط قراءات الشاشة بظهورها وحالة التطبيق، وتمرير AbortSignal؛ لا تلغي الشاشة المخفية قراءة يحتاجها مستهلك مرئي آخر. تُحرس أيضًا عمليات refetch والتحميل الإضافي اليدوية. لا يشمل الإلغاء الجديد الحفظ أو الرفع.
- `src/core/session-refresh.ts` و`auth.tsx`: مشاركة تحديث الجلسة الجاري داخل الهوية والجيل نفسيهما، دون تمديد صلاحية الجلسة. تعديل الحساب أثناء قراءة سابقة يفرض قراءة لاحقة، فلا تعيد البيانات القديمة بعد الحفظ.
- شمل الربط السوق والتفاصيل وإعلاناتي والمفضلة والمعلن والمحادثات والإشعارات والرسوم والمتابعات. لم تتغير مدد صلاحية الكاش الحالية أو نتائج البحث أو الفلاتر.
- `src/core/listing-publication.ts` وموفره: ملكية العملية على مستوى التطبيق بدل المحرر. المدخلات ومفاتيح الإنشاء والصور والنشر ثابتة لكل محاولة؛ النقر المكرر لا ينشئ عملية ثانية. تستمر العملية بعد التنقل وتتحقق من الهوية قبل المراحل وبعدها.
- `listing-publication-storage.ts`: سجل خاص بالحساب ووجهة السيرفر، ونسخ محلية خاصة للصور قبل أول كتابة. لا يُحفظ token أو رابط رفع موقّع. يتصالح الاستئناف مع السيرفر ويعيد استخدام الصور الناجحة؛ التعديل الصريح لمسودة فشلت عمليتها يستخدم المدخلات الجديدة بعد انتهاء المحاولة السابقة والتحقق من الملكية.
- «إعلاناتي» تدمج بطاقة العملية مع صفحات السيرفر دون تكرار، وتحافظ على الفلتر السابق. تتراجع البطاقة المحلية أمام سجل أحدث أو حذف مؤكد. لا تُرسل المعرفات المحلية إلى API.
- لا يظهر نجاح النشر قبل تأكيد ربط الصور المطلوبة وقراءة حالة الإعلان من السيرفر. `pending` تبقى قيد المراجعة. تقدم الصور لا يعيد جلب القائمة بعد كل صورة؛ تبقى إبطاليات الكاش والتحديث النهائي والتحديثات الفورية الضرورية.

## السيرفر

- `listing-similarity.ts` و`market-intelligence.ts` وكتلة التشابه في `repository.ts`: تجهيز الإعلان المرجعي مرة، والاحتفاظ بدرجات أفضل20 تدريجيًا. لم تتغير دفعات PostgreSQL أو المرشحات أو المقارن أو القراءة النهائية الحديثة للصور. يبقى فحص كامل مرشحي التصنيف؛ لا يوجد كاش TTL لنتائج التشابه.
- `direct-image-promotion.ts`: حجز نسخ حصري دائم باستخدام جدول `ImageObjectCleanup` الموجود. تُسجَّل الروابط قبل النسخ، ويحدث النسخ خارج معاملة قاعدة البيانات. يُعاد فحص المهمة والملكية والحالة، ويُغلق الحجز داخل معاملة إرفاق الصورة نفسها.
- `direct-image-uploads.ts` و`image-object-cleanup.ts`: لا يستطيع إكمال مكرر نسخ الملفات مرتين، ولا ينظف الإلغاء ملفات لا يزال ناقل نشط يكتبها. تبقى معالجة الاستجابة المفقودة وإعادة المحاولة والحذف المتزامن محمية. قد ينتظر تنظيف الملفات الملغاة فترة الحماية البالغة150ثانية؛ لا تضيف هذه الفترة انتظارًا إلى نجاح الرفع المعتاد.
- `direct-image-objects.ts`: نفس الروابط والصيغ والتحقق والنسخ المشروط، ضمن مهلة I/O محددة90ثانية؛ لا إعادة معالجة صور إضافية ولا تغيير للـWorker.

القياس المعزول، باستخدام QueryClient الحقيقي وخمس صفحات و20حدثًا أثناء القراءة:24GET و19إلغاء سابقًا، مقابل10GET وصفر إلغاء بعد التنظيم، مع تطابق النتائج والترتيب النهائي. و12تحديث جلسة متزامنًا تتشارك GET واحدة. لا تمثل هذه الأرقام اختبار حمل AWS أو عدد العملاء الممكن خدمتهم.

## الحدود والتفعيل

- التنقل داخل التطبيق لا يوقف النشر. إيقاف نظام التشغيل للعملية يوقف JavaScript؛ ما وصل إلى Cloudflare يمكنه متابعة المعالجة، ويستأنف التطبيق المتبقي عند فتحه. لا توجد هنا خدمة OS تضمن النشر أثناء إغلاق التطبيق.
- باص أحداث السيرفر الحالي محلي لكل نسخة؛ لذلك لم يُلغَ الاستدراك الدوري. ليست هذه الدفعة تحويلًا للباص إلى خدمة موزعة أو ضمانًا لوصول الحدث فورًا بين جميع نسخ App Runner.
- الاختبارات استخدمت قواعد وبيانات وهمية محلية، لا بيانات العملاء أو خدماتهم الحية. لم يظهر جهاز في ADB؛ يبقى فحص Android وiPhone الفعلي ودورة Cloudflare الحية خطوة منفصلة بعد البناء.
- تفعيل كود السيرفر يحتاج نشر النسخة الناجحة، وتفعيل تغييرات التطبيق يحتاج بناءً وتثبيتًا جديدين. لا يلزم ترحيل قاعدة بيانات أو تعديل Worker أو زيادة موارد AWS لهذه الدفعة.
