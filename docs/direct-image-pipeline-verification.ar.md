# نتيجة التحقق من مسار الصور المباشر

تاريخ التحقق: 27 أكتوبر 2026. هذا سجل للنسخة المحلية المعدلة في مستودعي
`SmartStoreAI` و`SmartStoreAI/AI`، وليس إثبات نشر على AWS أو Cloudflare.

## الفحوص المكتملة

| الفحص | النتيجة |
| --- | --- |
| اختبارات Node للسيرفر | 917 ناجحًا، 37 متخطى، صفر فشل؛ المجموع 954. |
| PostgreSQL المحلي المعزول | 36 ناجحًا، صفر فشل أو تخطٍّ، بما فيها 17 حالة لدورة الرفع الجديدة. |
| اختبارات Cloudflare Worker المحلية | 32 ناجحًا، صفر فشل أو تخطٍّ. |
| اختبارات تطبيق Expo | 212 ناجحًا، صفر فشل أو تخطٍّ. |
| TypeScript وESLint للسيرفر | ناجحان. |
| `pnpm check` للتطبيق | ناجح، ويشمل الأنواع والتنسيق. |
| بناء Next.js للإنتاج | ناجح. |
| `expo export --platform all` | ناجح للويب وAndroid وiOS، مع حزمتَي Hermes. |
| Wrangler 4.154.0 `deploy --dry-run` | ناجح، دون نشر. |
| `git diff --check` للمستودعين | ناجح. |

الاختبارات المشروطة المتخطاة في تشغيل Node العام لا تعد ناجحة. شغّلنا مجموعة
PostgreSQL المنفصلة فعلًا على `127.0.0.1:55432` دون استخدام قاعدة الإنتاج.
طُبّقت مهاجرات الميزة الأربع على قاعدتي التطوير والاختبار المحليتين فقط.

كان اختبار الأدلة القديم يفترض فشل الإتلاف بعد خطأ تخزين عابر واحد، بينما آلية
التخزين تعيد المحاولة. عدّلنا محاكاة الفشل لتستنفد محاولات التخزين الثلاث،
فأثبت الاختبار بقاء الأدلة وحالة الإتلاف المنتظرة ثم التعافي بإجراء جديد؛ لم
نخفف التحقق من البصمة أو الحماية أو صلاحيات الإتلاف.

المراجعة أثبتت أيضًا:

- استئناف مهمة الرفع دون تكرار الصورة أو إرسال Bearer إلى R2.
- منع ربط ملف بحساب بديل عند تبديل الهوية أثناء القراءة أو الرفع أو الانتظار.
- الاحتفاظ بالصورة المختارة حتى اعتماد `ready`، ومنع متابعة النشر قبل ذلك.
- استعادة المهام بعد إعادة فتح المحرر وإلغاؤها بعد تأكيد السيرفر، مع الحفاظ
  على الحقول المحلية وعدم إعادة صور حذفتها استجابة أحدث.
- حد الصور المشترك بين الحجوزات والرفع القديم عند الطلبات المتزامنة.
- منع اعتماد نتيجة قديمة بعد الحذف أو التعطيل، وتنظيف الملفات بعد حذف المورد.
- الحفاظ على إمكانية تصحيح صور الإعلان المرفوض دون تغيير قرار الإدارة أو نشره.
- الحفاظ على الصورة الرئيسية وتاريخ الإعلان، وتقييد أحداث المسودات بصلاحياتها.
- استمرار التنظيف بعد إيقاف الميزة، وإعادة محاولة حذف الكاش غير المكتمل،
  والاحتفاظ ببيانات المهام حتى تنظيفها ثم إزالة القديمة غير المرتبطة بصور.
- استمرار الرفع القديم، ومرفقات حمد، وصورة الحساب، ووضع الملفات المحلي.

## حدود النتيجة والنشر

لم تتوافر جلسة نشر أو بيانات إعداد R2/Cloudflare في بيئة العمل. لم ننشئ حاوية
أو طابورًا في الحساب الحقيقي، ولم ننشر Worker أو نغيّر إعداد AWS أو بيانات
الإنتاج، ولم نجر اختبار جهاز فعلي أو محرك Cloudflare Images الحي. محاكاة
bindings ونقل Expo لا تعادل اختبارهما على الخدمة والجهاز الحقيقيين.

لم يُنفذ فحص HTTP إضافي على خادم محلي مبني للإنتاج: رفضت مراجعة الموافقة الآلية
أمر تشغيل خادم الاختبار برسالة `blocked by policy`، دون تقديم سبب أكثر تفصيلًا.
لم نتجاوز هذا الرفض ولم نعد هذا الفحص ناجحًا. اختبارات صلاحيات معالجات API
المباشرة وبناء المسارات نجحت ضمن الفحوص أعلاه.

الميزة اختيارية ومعطلة افتراضيًا. الملفات جاهزة للإعداد وفق
[دليل التنفيذ والتفعيل](direct-image-pipeline.ar.md) و
[دليل Cloudflare](../cloudflare/image-pipeline/README.ar.md). لم تُرفع نسخة التطبيق
أو تُدفع التعديلات إلى المستودعات ضمن هذا العمل.
