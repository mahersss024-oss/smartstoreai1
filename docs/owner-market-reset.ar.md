# إعادة ضبط السوق قبل الإطلاق

المسار الإداري: `/admin/maintenance` ← **إعادة ضبط السوق بالكامل**. يظهر لمالك
المنصة المعرّف في إعدادات السيرفر فقط. لا يضيف صلاحية للمديرين المعيّنين.

يحذف الإجراء بيانات السوق في الجداول الـ27 عدا `User`، ويُبقي جميع صفوف
المستخدمين وحقولها وصور حساباتهم دون تعديل، بما فيها الأدوار وموافقات السياسات
وحالة الحذف السابقة. يشمل المسح الإعلانات والمحادثات والمفضلة والمتابعات
والتقييمات والبلاغات والأدلة والرسوم والعمولات والإشعارات ورسالة الموقع وسجل
الإدارة السابق. لا يغيّر مخطط القاعدة أو سجل الترحيلات أو متغيرات التشغيل.

يحتفظ الإجراء بسجل جديد للعملية وبالمهام اللازمة لحذف الصور وملفات الأدلة.
لا تعني نتيجة حذف السجلات أن ملفات Cloudflare قد حُذفت بالفعل. يستكمل عامل
التنظيف الموجود حذفها مع إعادة المحاولة عند فشل التخزين. تبقى سجلات روابط
الرفع الموقعة حتى انتهاء صلاحيتها والتنظيف النهائي، حمايةً من رفع يصل متأخرًا.
تُحمى الروابط التي لا تزال مستخدمة في صور الحسابات المحفوظة.

## التنفيذ من لوحة المالك

1. خذ نسخة احتياطية قابلة للاستعادة لقاعدة البيانات والملفات التي تريد حفظها.
2. افتح القسم واطلب المعاينة؛ لا يبدأ الحذف بفتح الصفحة.
3. راجع أعداد السجلات والحسابات المحفوظة والأدلة والرسوم التي يشملها الحذف.
4. اكتب السبب وأقرّ بالنسخة الاحتياطية وبإتلاف جميع بيانات السوق، بما فيها
   الأدلة المفتوحة أو المعلّقة والرسوم، ثم اكتب عبارة التأكيد المعروضة.
5. نفّذ مرة واحدة وانتظر النتيجة. عند فقد الاستجابة، راجع سجل الإدارة والبيانات
   قبل إرسال عملية جديدة؛ قد تكون المعاملة السابقة قد اكتملت.

المعاينة صالحة لعشر دقائق وموقّعة ومرتبطة بالمالك وبصمة البيانات. أي تغيير
مؤثر يتطلب معاينة جديدة. ينفّذ الحذف في معاملة واحدة، ويُلغى بالكامل عند
الفشل، دون تعطيل الحواجز أو استخدام `TRUNCATE`. لا يعدّل ذلك قواعد التنظيف
المحدود أو واجهات إتلاف الأدلة العادية.

يفشل التنفيذ عند وجود مهام نشطة أو تعارض أقفال أو تغير المخطط أو تجاوز
50,000 سجل إجمالي؛ يحتاج الحجم الأكبر مسار تنفيذ على دفعات بعد مراجعته.
لا تنفّذ العملية أثناء استقبال بيانات العملاء. التسجيلات الجديدة للإشعارات
تُعاد بواسطة التطبيقات عبر مسار التسجيل المعتاد بعد المسح.
