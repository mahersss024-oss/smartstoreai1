# تقرير تجهيز أدوات التطوير والتحقق

التاريخ: 20 أكتوبر 2026، بتوقيت الرياض. النطاق: جرد البيئة وتجهيز أدوات فحص
محلية واختبارها، مع الحفاظ على تغييرات المستخدم. لم تشمل المهمة إصلاح وظائف
التطبيق أو حذف الكود أو تعديل قواعد البيانات والإنتاج.

تحديث لاحق في اليوم نفسه: **نجح DevTools وLighthouse وظيفيًا** بعد عزل
مشكلة جمع بيانات الانتقال وتوفير طريقة قياس بسياق تصفح مهيأ. التفاصيل
والأوامر والأدلة في [تقرير المعالجة](browser-tools-repair-2026-10-20.ar.md).
وبطلب إصلاح لاحق، عولج أيضًا تصنيف اختبار الملف العام وتحذير lint وتتبع
مجلد البيانات في البناء؛ نجحت الاختبارات الكاملة دون فشل. راجع
[نتائج إصلاح المشروع](project-fixes-2026-10-20.ar.md). الأرقام والفقرات في
قسم Project verification أدناه تصف baseline تجهيز الأدوات قبل ذلك الإصلاح.
وجود الأدوات في القائمة لا يكفي لإثبات نجاحها.

## Agent/diagnostic tools

### Playwright

موجود مسبقًا: MCP `0.0.83` وPlaywright Test `1.63.0`. لم يُثبَّت تكامل
مكرر. اختُبر MCP باستدعاءات فعلية لصفحة معزولة ثم التطبيق التجريبي على
`127.0.0.1:3197`، ونجحت قراءة DOM والنقر والكتابة وتغيير حجم العرض.

- ظهر `lang=ar` و`dir=rtl` و10 إعلانات اصطناعية عند فتح السوق.
- أعاد البحث الحرفي عنوان الإعلان الاصطناعي الصحيح على سطح المكتب والمحمول.
- لم يظهر تجاوز عرض أفقي عند 1280×720 و390×844.
- Console: صفر أخطاء وصفر تحذيرات أثناء تفاعلات التطبيق المختبرة.
- Network: قراءة الجلسة وقائمة الإعلانات وطلبات البحث أعادت HTTP 200.
- اختبارات CLI الأربعة غطت اختيار واجهة مقدم الدخول والبحث؛ لم تنفذ تسجيل
  دخول حقيقيًا أو نشرًا أو دفعًا، ولا تمثل تشغيل مجموعة E2E كاملة.

أُغلق متصفح MCP وخادم الفحص بعد الانتهاء. الدليل التفصيلي في

## External systems

### GitHub

الخادم الرسمي `2.0.2` موجود، ونجحت قراءة الحساب وREADME عام عبر MCP. بقي
الاعتماد في مخزنه الحالي ولم يُطبع. Git المحلي هو الاختيار الأول للمعلومات
المتاحة محليًا.

أُضيف `GITHUB_READ_ONLY=1` في إعداد **المشروع**؛ أكد `codex mcp get` اندماجه
مع وسيط الربط الموجود. اختبار stdio مستقل بهذا الإعداد أعلن **27 أداة قراءة
دون أدوات كتابة**، ونجح استدعاء قراءة. الجلسة الحالية التي بدأت قبل الإعداد
قد تستمر بعرض الكتالوج القديم؛ يلزم إعادة تحميل نافذة VS Code وبدء محادثة
جديدة لتحميل الإعداد. لم تُستدعَ أداة كتابة حتى من الكتالوج القديم.

هذا تقييد لأدوات الخادم، ولا يضيّق صلاحيات الاعتماد الأصلية أو حساب GitHub.
لم تُنفذ push/merge أو تغييرات issues/settings/secrets. الدليل في
[github-readonly.log](../.data/environment-audit/github-readonly.log)
و[تقرير التكاملات](../.data/environment-audit/integrations.md)، والخيار موثق
في [الخادم الرسمي](https://github.com/github/github-mcp-server).

### PostgreSQL

العميل والخادم المحليان `17.11` موجودان. فُحصت القاعدتان المحليتان فقط على
`127.0.0.1:55432`، مع مطابقة `data_directory` المتوقع دون طباعته أو طباعة
سلسلة الاتصال. نجاح الاتصال لا يعتمد على نتيجة `pg_ctl status` الأولى
المضللة؛ أكد SQL أن الخادم هو العنقود المحلي المقصود. لم تبدأ هذه المهمة
عنقودًا جديدًا أو تستبدل الخدمة الموجودة.

| القاعدة | الجداول | الأعمدة | الفهارس | المفاتيح الخارجية | وضع المعاملة |
| --- | ---: | ---: | ---: | ---: | --- |
| smartstore_codex_dev | 26 | 237 | 97 | 33 | READ ONLY |
| smartstore_codex_test | 26 | 237 | 97 | 33 | READ ONLY |

أُضيف [postgres-inspect.ps1](../scripts/dev-tools/postgres-inspect.ps1) بفحص
وجهة ثابت واستعلام catalog ثابت داخل `BEGIN READ ONLY` و`ROLLBACK`، مع
`default_transaction_read_only=on` ومهل اتصال/استعلام محدودة. جرى تحليل
صياغته وتشغيله بنجاح على القاعدتين، دون قراءة صفوف العملاء.

**الحساب المحلي نفسه superuser وله CREATEDB وCREATEROLE وBYPASSRLS وحقوق
كتابة**؛ الحماية هنا للاتصال والمعاملة، وليست حساب قراءة محدودًا دائمًا.
لم تُنشأ أدوار أو تتغير grants؛ يتطلب ذلك تفويضًا منفصلًا من المستخدم.
PostgreSQL 17 يختلف عن تعريف Docker ذي الإصدار 16، فيلزم تطابق الإصدار عند
فحص سلوك حساس للإصدار. التفاصيل في [دليل القاعدة](local-postgres.md).

### Sentry وAWS

Sentry موجود ومتصّل؛ نجح `whoami` فقط. لم تُجلب أحداث أو محادثات أو بيانات
إنتاج. لا يثبت فحص الهوية القدرة على تشخيص مشكلة بعينها، ولا يثبت قيد

## Performance/security

### Lighthouse

**الحالة الحالية:** نجح تقرير desktop محلي صالح بالسكربت الدائم باستخدام
prepared browsing context وstorage reset مفعّل. لم تتغير COOP أو sandbox.
المحاولات الافتراضية أدناه تبقى فاشلة؛ لا تستخدم تقاريرها لقياس الأداء.
[الدليل والطريقة الحالية](browser-tools-repair-2026-10-20.ar.md).

ثُبت `13.5.0` في مجلد الأدوات المعزول، ونجح CLI version واتصال المتصفح
الابتدائي. **فشلت محاولتا القياس** على التطبيق المحلي بـ`NO_NAVSTART`، مع
`runtimeError` ودرجة performance تساوي `null`؛ لا يوجد قياس LCP/CLS/INP
صالح أو رقم أداء يمكن اعتماده من هذين التقريرين. وفق
[دليل النتائج الرسمي](https://github.com/GoogleChrome/lighthouse/blob/v13.5.0/docs/understanding-results.md)،
وجود runtimeError جاد يقتضي استبعاد نتيجة التشغيل.

حُفظت أصول المحاولة الثانية: trace يحتوي 18,789 حدثًا ومنها `navigationStart`
واحد و`TracingStartedInBrowser` واحد، وسجل DevTools يحتوي 255 حدثًا بما فيها
أحداث انتقال وتحميل. لذلك لا يُستنتج أن الحدث مفقود كليًا، ولا يُنسب الفشل
للتطبيق دون دليل. السبب الجذري غير مثبت. الأدلة:
[تقرير JSON](../.data/environment-audit/lighthouse-chromium153.json)،
[trace](../.data/environment-audit/lighthouse-chromium153-0.trace.json)
و[تقرير المتصفح](../.data/environment-audit/browser-inventory.md).

هذه محاولة قبول قدرة القياس فقط. لم تُجرَ مقارنة قبل/بعد أو قياسات ميدانية
أو تدقيق شامل للصور وCDN والكاش. أدوات vitals الموجودة بالمشروع متاحة
للمهمة اللاحقة؛ لم تُشغّل مجموعة جميع الصفحات هنا.

### k6 وdependency audit

k6 `2.2.0` موجود مسبقًا؛ لم يُعد تثبيته. نجح سيناريو القراءة العام الموجود
بـ**مستخدم افتراضي واحد، دورة واحدة، وستة طلبات HTTP** على loopback فقط،
بلا cookies حسابات وبمنع الكتابة والإنتاج. معدل أخطاء HTTP صفر؛ p95 نحو
359.7ms لهذه العينة الصغيرة وحدها. لا يثبت ذلك سعة الإنتاج أو تحمّل التزامن.
[سجل التشغيل](../.data/environment-audit/k6-smoke.log)
و[الملخص](../.data/environment-audit/k6-smoke-summary.json).

لم تُشغّل stress/spike/soak أو سكربتا الحمل القديمان اللذان يستهدفان نطاقًا
خارجيًا افتراضيًا ويحملان تزامنًا مرتفعًا. لم تُرسل طلبات نموذج أو عمليات
كتابة ضمن فحص الحمل.

نجح `pnpm audit` للتطبيق ولأدوات الفحص: **No known vulnerabilities found**
وقت التنفيذ. أعاد فحص الأدوات المحاولة بعد ECONNRESET ثم نجح. لا تعادل
النتيجة تدقيق أمان كاملًا للكود أو الصلاحيات. لم يُنفذ audit fix أو ترقية
major. [سجل التطبيق](../.data/environment-audit/dependency-audit.log)
و[سجل الأدوات](../.data/environment-audit/tools-audit.log).

## Safety

- وضع PostgreSQL المستخدم في الفحص READ ONLY، دون DDL/DML أو migrations
  أو fixtures في قاعدة البيانات؛ الحساب القائم واسع الصلاحيات كما سبق.
- GitHub مضبوط إلى read-only على مستوى خادم المشروع، واختُبر في عملية
  مستقلة؛ إعداد الجلسة القديمة يتطلب reload. Sentry استُخدم لقراءة الهوية فقط.
- لم يُربط AWS أو hosted database أو جهاز Native جديد. لم تُستدع أدوات
  GitHub/Sentry للتعديل، ولم تتغير production أو IAM أو DNS أو الخدمات.
- **لم تُعرض أو تنسخ أسرار** إلى المصدر أو التقارير أو أوامر العرض. ملفات
  الأسرار واعتماد Git Credential Manager بقيت محفوظة.
- التثبيت الجديد وإعداد MCP الجديد داخل المشروع. لم يُعدّل إعداد Codex
  العام أو يثبت برنامج عام جديد في هذه المهمة.
- لم تتغير `package.json` أو `pnpm-lock.yaml` أو schema/migrations أو وظائف
  التطبيق. بقيت تغييرات المستخدم السابقة في auth/profile/session كما كانت.
- لم يُحذف كود، ولم تُستخدم auto-fix أو `--force` أو عمليات Git مدمرة.
- خادم الفحص على 3197 أُوقف، ومتصفح الفحص أُغلق؛ تُرك PostgreSQL الموجود
  في حالته دون إيقافه. البيانات التجريبية والتقارير تحت `.data` المتجاهل.

### التشغيل المتكرر داخل VS Code

أُضيفت المهام التالية في [tasks.json](../.vscode/tasks.json):

1. `SmartStore: Install isolated diagnostic tools`: تثبيت النسخ الثلاث المحددة
   فقط داخل `.data`، مع تخطي التثبيت عند وجود النسخ بالفعل.
2. `SmartStore: Inspect PostgreSQL metadata (read only)`: الاستعلام الثابت
   الموثق؛ لا يبدأ الخادم ولا يغير القاعدة.
3. `SmartStore: Knip audit (no fixes)`: تقرير CLI دون إصلاح أو حذف، مع
   `CI=1` و`K6_BASE_URL` على loopback لقراءة إعداد load-browser دون استهداف
   خدمة خارجية؛ هذه القراءة لا تشغّل خادمًا أو حملًا.

```powershell
# إعادة إنشاء أدوات الفحص فقط عند غيابها:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev-tools\install-audit-tools.ps1

# فحص catalog للقواعد المحلية الموجودة دون تغييرها:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev-tools\postgres-inspect.ps1 -Database all

# تقرير الكود المشتبه؛ exit 1 مع وجود نتائج أمر متوقع:
$auditPreviousCi = $env:CI
$auditPreviousLoadUrl = $env:K6_BASE_URL
try {
    $env:CI = '1'
    $env:K6_BASE_URL = 'http://127.0.0.1:3102'
    node .data/environment-audit/tools/node_modules/knip/bin/knip.js --config knip.jsonc --reporter json --no-progress
}
finally {
    $env:CI = $auditPreviousCi
    $env:K6_BASE_URL = $auditPreviousLoadUrl
}
```

فحص تثبيت الأدوات المتكرر نجح دون تنزيل نسخة ثانية، ونجح parser للسكربتين.
نجح فحص صياغة مساعدَي Node المؤقتين، وصحة JSON لمهام VS Code (8 في
الجولة الأولى، ثم 10 بعد معالجة المتصفح)، واكتمال حقول مصفوفة الأدوات الـ28. كشفت إعادة lint مراجع require
في مساعد الفحص المؤقت؛ صُحح المساعد باستيرادات ديناميكية وأُزيل متغير مؤقت
غير مستخدم، ثم نجح lint مجددًا دون تغيير قواعده أو شيفرة التطبيق.
أعد تحميل VS Code عبر `Developer: Reload Window` ثم افتح محادثة Codex جديدة
داخل المشروع لتحميل إعداد MCP المحلي عند الحاجة. بعد هذه الجولة نجح اختبار
وظيفي مستقل للأداتين، بما فيه MCP المباشر؛ راجع
[طريقة التشغيل الحالية](browser-tools-repair-2026-10-20.ar.md) ومهمتي
DevTools وLighthouse الجديدتين في VS Code.
